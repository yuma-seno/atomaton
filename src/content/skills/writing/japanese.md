# 人に向けて日本語で書く

## 何に効き、何が優先するか

このrunが**人に向けて書く日本語**すべてが対象になる — 報告コメント、質問、相談、プルリクエストの本文、サブIssueの本文、次の担当への引き継ぎ。

対象外は、コード、コミットメッセージ、機構が固定で持っている英文、報告契約そのものの見出し語。

**報告の契約が優先する。** システムプロンプトの報告は四つの部からなり、そのうち三つに上限がある。残る「確かめられなかったこと」には上限がなく、切り詰めてはいけない。このスキルはその枠の中で文を整えるだけで、枠を変えない。衝突したら契約に従う。

**投稿する前に、一度だけ読み直す。** 下書きをこの原則で通し、直してから出す。報告はrunの最後に一度しか書かれないので、読み直しの機会はここしかない。

以下は [yomiyasu](https://github.com/nanaism/yomiyasu) v2.5.0（MIT）の変換原則を、推敲ではなく**生成向け**に組み直したもの。上流は追わない。

## 一文

**主語と述語を離さない。** 一読で「誰が何をしたか」が追えること。修飾を主述の間に長く挟むと、読み手は述語を探して戻る。挟むなら文を分ける。

> ✗ この変更は、前回の議論で保留にされていた点を踏まえたうえで、今回の判断として取り込むことにしました。
> ○ 前回はこの点を保留にしていました。今回は取り込みます。

**指示語の先を確定させる。** 「これ」「その方針」「前者」は、直前の一文だけを読んで指す先が決まる位置に置く。決まらないなら名詞に戻す。

**長さの目安は一文30〜45字、読点は0〜2個。** 超えたら、読点を足すのではなく文を割る。間を作るためだけの読点は外す。並んだ語句を区切る読点、外すと係り先が変わる読点は残す。

## 文末

**終わったことを「〜します」と書かない。** 報告で最も多い病。直したなら「修正しました」、いま直しているなら「修正しています」、これからなら「修正します」。この三つを文末で書き分ける。

**言い切りの強さを変えない。** 確かめたことは「〜です」、推測は「〜と考えられます」。弱めるのは事実でないときだけ。

**文末を散らすこと自体を目的にしない。** 同じ文末が続いて単調なら、語順と文のまとめ方で整える。文の働き（説明・依頼・報告）は変えない。

## 語彙

**比喩を平易な動詞に戻す。** 次の語は上流の書き直し例で言い換えられたもの。同じ語を機械的に置き換えるのではなく、この種の語を書いたら一度立ち止まる。

| 書いてしまいがち | 言い換え |
| --- | --- |
| 静かに壊れます | 気づかないうちに損なわれます |
| 解像度が一段上がります | 理解が一段深まります |
| 地味に効いてきます | 目立たないながらも役立ちます |
| 時間を溶かす | 時間を無駄にする |
| 原因を潰す | 原因を取り除く |
| 共通側に倒す | 共通のものに統一する |
| 黙ってスキップする | 表に出さずにスキップする |
| 手触り感 | 操作感 |

**道具に意志を貸さない。** 「テストが叫ぶ」「設定が怒る」は、何がどうなるかに書き直す。道具の客観的な動作を述べる文（「この関数は例外を返す」）はそのまま残す。

**大げさな名前にしない。** 仕組みを「OS」「契約」「正本」と呼ぶのは、役割に合う語があるときは避ける。意思決定OS → 意思決定の枠組み。

**「単なるXではなくY」を減らす。** 対比が読み手の判断を変えるときだけ残し、それ以外はYを直接述べる。

## 構成

**結論を最初に置く。** 前置き、経緯、免責を先に並べない。

**予告だけの文を書かない。** 「以下の3点が挙げられます」は、中身を書いてからその文が要るか決める。要るなら中身と同じ一文にまとめる。宣言した数は項目数と一致させる — 一致しないなら数を書かない。

**一段落に一つの話題。** 話題が変わったら段落を変える。段落の最初の文で何の話かが分かるようにする。

**接続詞は、何と何をつないでいるか確かめてから置く。** 「しかし」「そのため」「また」は、前の文との関係が実際にその関係であるときだけ。

**余談は末尾に一文だけ。** 本題の途中に差し込まない。

## 箇条書きと折りたたみ

**太字ラベルとコロンの形を避ける。** 「**検証**: 済み」ではなく、ラベルを説明の文に溶かす — 「検証は済んでいます」。

**箇条書きは、並列が明確なときだけ。** 手順、選択肢、対比する項目。文章で書けるものを項目に割らない。

**`<details>` は検証のためのものを畳む。** 根拠の一覧、再現手順、測定値、引用、棄てた選択肢。summaryは中身を名指しする — 「検証: テスト全件pass」「棄てた選択肢」。中身のないsummaryは、畳んだことが情報を隠しただけになる。

**結論、質問、次の一手は畳まない。** 読み手が行動するために開かずに済むこと。折りたたみは入れ子にしない。

**太字は契約が構造を示すために使う。** 本文の強調には使わない。

## 削る基準

**読み手の次の行動が変わらない情報は、削るか折りたたむ。** 判断材料にならない過程は書かない。

**過程の羅列を結果の一文に置き換える。** 「〜を確認しました。〜も確認しました」は「確認した結果、〜でした」になる。

**同じ結論を二箇所に書かない。** 結論、根拠、次の一手のどれか一箇所に置く。

**測っていないことを、測ったように書かない。** 資料、原文、会話にない数値・原因・感情を足さない。確かめていないことは「確かめていない」と書く。

## 表記

**補助動詞と形式名詞はかなにする。** 出来ます → できます、する事が → することが、〜して下さい → 〜してください。

**それ以外の表記の揺れは直さない。** 送り仮名や英字の大小を整える作業は、読みやすさを上げない。

**英数字の前後の空白は、周囲の書式に合わせる。** 文中で全角と半角を混ぜない。
